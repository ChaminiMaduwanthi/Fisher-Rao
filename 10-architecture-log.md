# The network block is gone — and the pipeline now runs on three architectures

**Date:** 11 August 2026
**Status:** ✅ **TLS fixed, and GPT-2 and Pythia pass every correctness check.** Stage 4's "≥ 3 models" exit criterion is no longer blocked, and neither is RQ3a as literally posed.
**Reproduce:** `python -m fisherrao.net` (diagnosis), `python check_architectures.py` (the four rungs)

## 1. The TLS block — diagnosed, and fixed without weakening anything

Stage 0 recorded that HuggingFace was unreachable and that no new model could be downloaded ([05-stage0-log.md](05-stage0-log.md) §0). It correctly refused the tempting fix — `verify=False` — and left the problem open. The whole project has run on one model since.

**The culprit, named.** The certificate `huggingface.co` presents on this machine is issued by

```
CN=Avast Web/Mail Shield Root, OU=generated by Avast Antivirus for SSL/TLS scanning
```

so the antivirus is terminating and re-signing every TLS connection. That root, present in both `LocalMachine\Root` and `CurrentUser\Root`, is **malformed**:

```
basicConstraints    critical=False    ca=True
```

RFC 5280 §4.2.1.9 requires `basicConstraints` to be **critical** in a CA certificate. OpenSSL 3.x enforces that; Windows' own verifier does not. Hence browsers work and Python does not.

**What did not work, and it is worth recording because it is the obvious first move:** exporting the Avast root and appending it to certifi's bundle. Tried and measured — still fails identically. The error is not *"this CA is untrusted"*, it is *"this CA is malformed"*, so trusting it harder achieves nothing.

**What works.** `fisherrao/net.py` routes Python's certificate verification through the **operating system's** verifier (`truststore`), which is the same component Edge and Chrome use and which tolerates this one non-critical-extension defect.

> This is **not** `verify=False` and not a security downgrade. Certificates are still verified, hostnames are still checked, expired and untrusted certificates are still rejected. The clean fix remains disabling Avast's HTTPS scanning — that is the user's call, and this makes the project usable without asking for it.

`fisherrao/__init__.py` enables it before anything imports `huggingface_hub` (which caches an SSL context at import time). `FISHERRAO_NO_TRUSTSTORE=1` or `HF_HUB_OFFLINE=1` skips it, so offline reproductions are unchanged.

**Verified:** `huggingface.co` returns 200; `gpt2` and `EleutherAI/pythia-160m` download and load.

## 2. 🔴 Unblocking the network exposed the next blocker immediately

`gpt2` and `pythia-160m` both failed to load: *"could not locate the final norm"*. The pipeline had only ever run against one RMSNorm Llama, and three separate things were hardcoded to Llama's spelling.

| | base attr | blocks | final norm | norm type |
|---|---|---|---|---|
| Llama / SmolLM2 | `.model` | `.layers` | `.norm` | RMSNorm |
| GPT-2 | `.transformer` | `.h` | `.ln_f` | **LayerNorm** |
| GPT-NeoX / Pythia | `.gpt_neox` | `.layers` | `.final_layer_norm` | **LayerNorm** |

Now resolved through HF's own `base_model_prefix` plus a list of known attribute names, with an error message that names what to add if a fourth architecture appears.

### 2.1 Two real bugs found while doing it

**(i) The LayerNorm bias was applied in the wrong place.** `apply_norm` computed `g*z + g*b` instead of `g*z + b` — the bias was added to the normalised term and the gain then multiplied the sum. **Exactly zero error on SmolLM2** (RMSNorm, no bias), and a silent, plausible-looking error on every LayerNorm model — i.e. on both models the cross-architecture comparison needs. Caught by checking against the model's own norm module rather than by reading the code.

**(ii) The embedding hook was wrong for GPT-2.** `residual_stream` captured entry 0 from a hook on the token embedding. On GPT-2 the residual stream entering block 0 is `wte + wpe`, so the positional term would have gone missing and layer 0 would have been quietly incorrect. Replaced with a forward **pre**-hook on block 0, which is literally "whatever enters the first block" and is architecture-independent.

### 2.2 🎯 LayerNorm has TWO exact null directions, not one

This is the part that does not transfer, and `metrics.py` had already flagged the risk.

RMSNorm's Jacobian is `A = diag(g)(1/r)(I − ĥĥᵀ)` — one null direction, `h` itself, which is the entire basis of the quotient formulation. LayerNorm's is

```
A = diag(g) (1/s) ( I − 11ᵀ/d − z zᵀ/d ) ,    z = (h − μ)/s
```

which annihilates **two**: the radial direction as before, **and the all-ones direction from the mean subtraction**. So on GPT-2 and Pythia the metric has rank ≤ `d − 2` and the quotient is by a 2-plane, not a line. `LM.null_directions()` returns the right basis per architecture and `curvature.null_projector()` uses it everywhere the radial projector used to be inlined.

> ⚠️ **Measured impact: none, at `k` = 5.** All-ones leakage into the retained frame under the *old* radial-only projector is **0.0000** on both models. Selecting the top-`k` eigenvectors by descending eigenvalue already excludes an exactly-null direction, because its eigenvalue is exactly 0 and `k` ≪ `d`.
>
> **So this is a guard, not a bug fix, and no published number changes because of it.** It is still the right default: the guard binds when a null direction is only *numerically* null, which is the regime `k` selection pushes into as `k` grows — and that is exactly where a silently `pinv`-absorbed singular metric returns a plausible wrong answer instead of failing.

|---|---|---|---|

This is the same minority [07-stage4-log.md](07-stage4-log.md) §1.1c identified from the `K` quantiles and argued is real geometry rather than numerical failure. **It is now visible in three architectures**, at a consistent 6–12% rate, which is the strongest evidence yet that it is a property of these manifolds and not of one model's conditioning.

⚠️ **`n` = 12 points per layer, 16 planes per point** — so "no negative plane found" at a point means none among 16 samples, not none in the tangent space. The 88–94% figure is an upper bound on the all-positive fraction.

### 3b.1 Why is Pythia the volume outlier? — **four** hypotheses tested, none survives

> ✅ **Superseded by §3b.2: with six models there is no Pythia outlier.** This section is kept for the hypotheses it eliminates and for the retraction it records.

> 🔴 **A first version of this section confidently answered "the final-norm gain" and was wrong.** It rested on a 24-point convenience sample (8 sentences × 3 layers, last token only) whose per-model entropies ranged from 0.46 to 5.73 nats. On a randomly drawn 220-point sample across all layers the conclusion reverses. **The retraction is left in place because the failure mode — a confidently reported number from a convenience sample — is the one this project keeps hitting.**

**Hypothesis 1 — embedding tying. ❌ Ruled out.** `JackFram/llama-160m`, a Llama with **untied** embeddings, has the untied E5 behaviour ([09-e5-log.md](09-e5-log.md) §2.2) but **not** the volume offset: median log-vol −0.067, sitting with the tied models rather than with Pythia's +0.342.

**Hypothesis 2 — the final-norm gain. ❌ Ruled out.** The metric is `G = (1/r²)·P diag(g) Uᵀ Σ_p U diag(g) P`, so an isotropic gain `c` shifts `½·mean(log λ)` by exactly `log c`, and `mean(log|g|)` is the corresponding post-hoc correction. Pythia's gain really is much larger (`mean log|g|` = 1.90 against 0.27–1.02). **But correcting for it makes the models *less* alike, not more:**

| sample | raw spread | **gain-corrected spread** |
|---|---|---|
| 24-point last-token convenience sample *(the retracted basis)* | 1.332 | 0.857 ✅ *looked like a fix* |
| **220 random points, all layers** | **0.691** | **0.936** ❌ *worse* |
| **220 random points, entropy matched to [2,5) nats** | **0.662** | **1.004** ❌ *worse* |

**Hypothesis 3 — predictive entropy. ❌ Ruled out.** [08-rq3a-log.md](08-rq3a-log.md) §5.5 showed log-volume tracks concentration at ρ ≈ +0.8, and the four models produce very different entropies on the same corpus, so this was the obvious remaining candidate. **Restricting all four to entropy ∈ [2,5) barely moves the spread: 0.691 → 0.662.**

|---|---|---|---|
| gpt2 | 2.33 | −0.333 | −0.124 |
| SmolLM2-135M | 1.07 | −0.278 | +0.233 |
| llama-160m | 4.11 | −0.098 | −0.053 |
| **pythia-160m** | 1.56 | **+0.358** | **+0.538** |

> ## **Pythia's volume offset is real, smaller than first reported (spread 0.69, not 1.33), and unexplained.**
>
> It is not embedding tying, not the norm gain, and not predictive entropy. It survives matching on the one covariate known to drive log-volume.

>
> "Pythia is the volume outlier" was an artefact of the four-model sample. With six there is no outlier — there is a **1.14-wide spread** with a tied model at each end.

**Rank correlations against log-volume, n = 6 models** (so nothing here is significant; this is hypothesis ranking, not testing):

| candidate | ρ |
|---|---|
| **mean log\|g\|** | **+0.657** |
| vocab size | +0.543 |
| entropy | −0.429 |
| log‖U‖ median | +0.143 |
| tied / untied | −0.143 |
| width `d` | +0.086 |
| log‖U‖ spread | +0.029 |

**And this partly rehabilitates the gain, in a way that explains §3b.1's failed correction.** The gain is the leading candidate (ρ = +0.657) — but the OLS slope of log-volume on `mean log|g|` is **0.296, not the 1.000 the isotropic-gain algebra predicts.** So subtracting the full `log|g|` over-corrects by **3.4×**, which is exactly why it *increased* the spread. The gain matters at about a third of the rate a scalar gain would, consistent with it being **anisotropic** and interacting with which directions the top-`k` selection retains.

**Settled position on the volume element across models:**

1. **There is no Pythia outlier.** The four-model observation that started this does not survive two more models.
2. **Cross-model log-volume varies by ~1.1 nats/dimension** and the strongest single correlate is the norm gain, at about a third of the naive slope — but at `n` = 6 models nothing is established.
3. **The practical rule is unchanged and is the part that matters:** use log-volume *within* a model across layers, after the sphere correction. Cross-model comparison mixes at least the gain, the vocabulary and the entropy, and this project has now spent three attempts failing to disentangle them at `n` = 6.

**What still stands, and it is the part that matters for the thesis:** log-volume carries at least two artifacts that have nothing to do with geometry — the `1/r²` residual-norm term (§2.2, fixed by measuring on the sphere) and its concentration dependence ([08-rq3a-log.md](08-rq3a-log.md) §5.5, where a structure-free scramble reproduces the whole layer profile at ρ = +0.967). **Use it within a model across layers; treat cross-model comparisons as open.**

**Hypothesis 4 — unembedding row-norm uniformity. ❌ Ruled out, by intervention.**

Of the four models, **Pythia's unembedding row norms are almost perfectly uniform** — IQR/median **0.012**, against 0.14–0.24 for the others. That is a real and unusual property, and a plausible mechanism: a uniform `‖U row‖` distribution should inflate the metric's smaller eigenvalues and so raise log-volume.

With `n` = 4 models a correlation is meaningless (Spearman on four points can only take ±1, ±0.8, ±0.4, ±0.2), so this was tested by **intervention** instead: rescale every unembedding row to the median norm — same directions, same `p` from the real model — and see whether log-volume moves toward Pythia's.

| model | IQR/med | log-vol real | log-vol **norm-equalised** | shift |
|---|---|---|---|---|
| gpt2 | 0.142 | −0.334 | +0.005 | **+0.340** |
| SmolLM2-135M | 0.241 | −0.270 | −0.228 | +0.042 |
| llama-160m | 0.214 | −0.094 | −0.134 | −0.040 |
| **pythia-160m** | **0.012** | **+0.362** | **+0.349** | **−0.013** |

**The design has its own positive control and it passes**: Pythia, whose norms are already uniform, barely moves (−0.013). So the manipulation does what it claims.

**But it does not explain the offset.** Row-norm spread does not predict the shift — gpt2 (IQR 0.142) moves +0.340 while SmolLM2 (IQR 0.241, *more* spread) moves +0.042 and llama moves *down*. And after equalising, **Pythia is still the outlier by a wide margin** (+0.349 against the next highest +0.005); the cross-model spread falls only from 0.696 to 0.577.

**Vocabulary size is ruled out by inspection**: llama-160m has 32000 against 49152–50304 for the rest, and it is *not* the volume outlier.

> ## **Four candidate mechanisms tested, four rejected: embedding tying, the norm gain, predictive entropy, and unembedding row-norm uniformity.**
>
> Pythia's log-volume offset is real, modest (spread 0.69 across four models), and **unexplained**.

**The reading this supports** is the one §3b.1 already reached from the failed gain correction: **log-volume is not a cross-model quantity.** It is plausibly the sum of many small parameterisation differences, none individually dominant — which is exactly what four failed single-cause hypotheses look like. Chasing a fifth is lower value than simply not making cross-model volume claims.

**This also lands on the right side of [08-rq3a-log.md](08-rq3a-log.md) §5.5.** Curvature — the quantity that carries learned structure — is the one that agrees across architectures. Volume — the quantity that largely reads concentration — is the one that does not. Consistent, and worth saying explicitly in Chapter 6.
